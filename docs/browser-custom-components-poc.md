# Эксперимент: TGZ как готовый браузерный ESM

Это рабочие заметки по следующему этапу интеграции кастомных React-компонентов.
Старый эксперимент с `npm install` и виртуальным модулем Vite больше не используется в этой ветке.

## Задача

Автор библиотеки предварительно собирает JS и CSS командой `npm run make` в
[activeBook-custom-test](https://github.com/KrimsonKing1337/activeBook-custom-test).

В результате в книге хранятся **готовые** `.tgz`:

```text
MyBook/
  book.json
  package.json
  assets/
  dependencies/
    activebook-custom-test-0.0.6.tgz
```

Внутри `.tgz` находятся `package.json`, `active-book.json`, `dist/index.js` и `dist/style.css`.
`active-book.json` содержит путь к ESM и стилям, а не npm-subpath.

## Что происходит в редакторе

1. Нажимаем **Импортировать .tgz**. Браузер выбирает файл и читает манифест.
2. Подтверждаем доверие стороннему JavaScript. При необходимости архив копируется в `dependencies/`.
3. `LocalProjectStorage` записывает ссылку `file:./dependencies/...tgz` в `package.json` книги.
4. Браузер распаковывает TGZ через `DecompressionStream('gzip')`.
5. `packages/book-builder/src/customComponents/browser.ts` выдаёт содержимому JS Blob URL, а CSS подключает через `<link>`.
6. `import(/* @vite-ignore */ url)` загружает ESM **нативно, без npm install и без Vite-плагина**.
7. Реестр редактора обновляется через `useSyncExternalStore`; Tiptap NodeView получает новый компонент.

Компоненты из уже сохранённой книги автоматически загружаются после её открытия.
Проверенные автором архивы запоминаются по SHA-256 в локальном браузерном хранилище.

## Что происходит при сборке книги

Book Builder по-прежнему собирает **само приложение книги** через Vite.
Но библиотеку он **не пересобирает и не устанавливает**.

- `package.json` и `dependencies/*.tgz` передаются из проекта во временную сессию сборки.
- Архивы копируются в `public/dependencies` и затем в готовый `dist-book/dependencies`.
- Из `package.json` генерируется `custom-components.json` со ссылками на TGZ.
- После открытия готовой книги браузер загружает TGZ по URL относительно `document.baseURI`, распаковывает
  и динамически импортирует тот же браузерный ESM.

Этот PoC переносит `.tgz` в итоговую книгу целиком. Более компактную распаковку на этапе выпуска
можно сделать позже, без изменения контракта автора пакета.

## Общий React

Бойлерплейт использует экспериментальный адаптер `globalThis.__ACTIVE_BOOK_HOST__`.
Его значения `react`, `jsxRuntime`, `jsxDevRuntime` устанавливает общий загрузчик
из тех же React-модулей, что использует редактор или книга.

Это не публичный стабильный API. Для опытного разработчика пока следует рекомендовать
официальный бойлерплейт, либо повторение его адаптера.

## Проверка

1. В репозитории `activeBook-custom-test`: `npm install && npm run make` (архив версии **0.0.6**).
2. Переключиться на `feature/custom-components-manifest-poc` в репозитории редактора.
3. `npm install && npm run dev`; создать/открыть книгу и импортировать новый TGZ.
4. Проверить кнопку «Добавить Счётчик», работу хуков и стили.
5. «Собрать книгу», открыть результат через локальный HTTP-сервер и проверить тот же счётчик.
6. Для CLI-примера положить архив в `example-book/dependencies/` и запустить `npm run build:book`.
7. Запустить `npm run typecheck -w @active-book/book-builder`, `npm run test -w @active-book/book-builder`
   и `npm run build:editor`.

## Ограничения PoC

- Только **один самодостаточный браузерный JS-файл** для точки входа; CSS отдельными файлами.
- Для динамической загрузки Blob ESM требуется политика безопасности страницы, разрешающая такие модули.
- В CSS пока нет механизма переписывания относительных URL ресурсов. Вкладывай изображения через
  `data:` URL или решай пути в собственной сборке.
- Сторонний JS исполняется в контексте редактора/книги, без песочницы. Загружать только доверенные библиотеки.
- Публичные общие зависимости кроме React, версии ABI, мультимодульные чанки и оптимизация размера финальной книги
  будут спроектированы отдельно.
